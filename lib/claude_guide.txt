4. AUTHENTICATION & VERIFICATION FLOW (FULL DATA FLOW)
==============================================================

APP LAUNCH
  main.dart
  └─ Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)
  └─ runApp( ChangeNotifierProvider<AuthService> → MaterialApp → Wrapper() )

WRAPPER (wrapper.dart)
  └─ StreamBuilder on AuthService.user (Firebase auth state stream)
      ├─ stream == null (loading)  → LoadingWheel
      ├─ user == null              → SignIn screen
      └─ user != null              → VerifyScreen

----- REGISTRATION PATH -----
  register.dart
  └─ User enters email + password
  └─ authService.registerWithEmailAndPassword()
      └─ FirebaseAuth.createUserWithEmailAndPassword()
      └─ Returns User(uid) → Wrapper sees new user → VerifyScreen

----- SIGN IN PATH -----
  sign_in.dart
  └─ User enters email + password
  └─ authService.signInWithEmailAndPassword()
      └─ FirebaseAuth.signInWithEmailAndPassword()
      └─ Returns User(uid) → UserData.uid = uid
      └─ Wrapper sees change → VerifyScreen

----- EMAIL VERIFICATION GATE -----
  verify_screen.dart
  └─ Gets FirebaseAuth.instance.currentUser
  └─ await user.reload()  (refreshes verification status)
  └─ if user.emailVerified == false:
      └─ send_Email.dart
          ├─ Calls user.sendEmailVerification()
          ├─ Timer fires every 5 seconds
          ├─ Each tick: user.reload() → check emailVerified
          ├─ Resend button available after 60 seconds
          └─ On verified: Navigator → VerifyScreen (re-evaluates)
  └─ if user.emailVerified == true:
      └─ VerifyUser().setUid()
          ├─ Queries "membersPublic" collection for doc where email == userEmail
          ├─ UserData.setUserData(snapshot) — populates ALL UserData fields:
          │    docID, uid, membersPublicId, name, email, phoneNumber,
          │    gaam, address, city, state, zip,
          │    spouse, father, mother, child1–child5,
          │    accountExists, isAdmin
          └─ Updates Firestore: accountExists = true
      └─ AdminVerifyScreen

----- ADMIN CHECK GATE -----
  admin_verify_screen.dart
  └─ VerifyUser().isAdmin()
      └─ Reads "isAdmin" field from membersPublic doc
  ├─ isAdmin == true  → AdminHomeWrapper (admin dashboard)
  └─ isAdmin == false → HomeWrapper (member dashboard)

----- SIGN OUT -----
  authService.signOut()
  └─ FirebaseAuth.instance.signOut()
  └─ UserData.resetUserData()  (clears all cached fields)
  └─ Wrapper detects null user → SignIn screen

----- DELETE ACCOUNT -----
  authService.deleteAccount()
  └─ authService.reauthenticateUser(email, password)  (required first)
  └─ FirebaseAuth.currentUser.delete()
  └─ UserData.resetUserData()

5. SERVICES LAYER (BUSINESS LOGIC)
==============================================================

--- auth.dart (AuthService) ---
  Extends ChangeNotifier, registered at Provider root.
  Key methods:
    user (getter/stream)            → Stream<User?> from Firebase auth changes
    _userFromFireBase(fbUser)       → Converts Firebase user → app User model, sets UserData.uid
    signInWithEmailAndPassword()    → wraps Firebase signIn, returns error string or null
    registerWithEmailAndPassword()  → wraps Firebase createUser, returns error string or null
    signOut()                       → signOut + UserData.resetUserData()
    deleteAccount()                 → reauthenticate → delete Firebase user
    reauthenticateUser()            → EmailAuthProvider.credential → reauthenticate
    changeEmail()                   → reauthenticate → updateEmail()

--- verify_user.dart (VerifyUser) ---
  verifyEmail()   → checks if email exists in "membersPublic" (used at registration?)
  setUid()        → queries membersPublic by email → UserData.setUserData(snapshot)
                    → updates accountExists = true in Firestore
  isAdmin()       → reads "isAdmin" field from membersPublic doc, returns bool

--- access_data.dart (AccessData) ---
  searchDocByEmail()    → queries membersPublic where email == currentUser.email
  updateField(docId, field, value)  → Firestore doc update (merge: true)
  getField(docId, field)            → reads single field value
  searchCollection(collection, field, text)
                        → prefix search: field >= text && field < text+'zzz...'
                        → only runs if text.length > 3
  docSnapshotToMap(snapshots)       → converts List<DocumentSnapshot> → List<Map> with docID
  addDocument(data)     → adds doc to "membersPublic"
  getAllDocuments()      → gets all docs from collection
  deleteDoc(docId)      → deletes document
  newDocument(collection, data)     → generic doc creation

  SEARCH LIMITATION: Firestore prefix search is case-sensitive.
  The app capitalizes input via TextFormatting to match title-cased DB values.
  This only works if users store names in Title Case — fragile.

--- edit_user_info.dart (EditInfo) ---
  submitUserChanges(context, docId, initialValues, currentValues)
    → diffs initialValues vs currentValues
    → only calls updateField() for changed fields
    → updates UserData cache fields for immediate UI refresh
  showEditPopUp(context, docId)
    → builds modal dialog with TableRowColumnsAdmin for each editable field:
       Name, Email, Phone, child1–5, Father, Mother, Spouse,
       Gaam, Address, City, State, Zip

--- search_helper.dart (SearchHelper) ---
  performSearch(text, setState)
    → tries searchCollection by name first, then gaam, then city
    → sorts results alphabetically by name
    → updates internal results list, calls setState callback
  showPopUp(context, data)         → read-only user detail dialog
  showPopUpAdmin(context, data)    → editable user detail dialog (admin only)
    → includes phone call + mailto buttons via url_launcher
  submitChanges(context, docId, initialValues, currentValues)
    → same as EditInfo.submitUserChanges but for searched users
  stateUpdate(setState)            → re-runs performSearch to refresh results

--- announcement_helper.dart (AnnouncementHelper) ---
  timestampToString(timestamp)     → Firestore Timestamp → "Month-Day-Year at H:MM AM/PM"
  dateTimeMonth(monthNumber)       → int → month name string
  sortListByDate(list)             → sorts announcements newest-first
  addAnnouncement(name, content)   → writes new doc to "announcements" collection

--- error_handling.dart (ErrorHandling) ---
  getErrorMessage(errorCode)       → maps Firebase error codes to readable strings:
    invalid-email, user-disabled, user-not-found, wrong-password,
    email-already-in-use, too-many-requests

--- wrapper.dart (Wrapper) ---
  Stateless widget, root of authenticated app tree.
  StreamBuilder on Provider.of<AuthService>.user:
    null stream  → LoadingWheel
    null user    → SignIn()
    user exists  → VerifyScreen()

  - Timer.periodic(5 seconds) polls user.reload() + emailVerified
  - 60-second cooldown before resend allowed
  - On verified: Navigator.pushReplacement → VerifyScreen

admin_verify_screen.dart
  - FutureBuilder on VerifyUser().isAdmin()
  - Routes to AdminHomeWrapper or HomeWrapper

reset_password.dart
  - Single email field
  - Calls FirebaseAuth.sendPasswordResetEmail()
  - 60-second cooldown for resend

User.dart defines two classes:

  class User { String? uid }
  → Simple wrapper around Firebase user, used in auth stream

  class UserData (static/singleton-like pattern)
  → Static fields holding logged-in user's data for the session:
      static String? docID            Firestore document ID in membersPublic
      static String? uid              Firebase Auth UID
      static String? membersPublicId  (same as docID typically)
      static String? name
      static String? email
      static String? phoneNumber
      static String? gaam             Community group identifier
      static String? address
      static String? city
      static String? state
      static String? zip
      static String? spouse
      static String? father
      static String? mother
      static String? child1 – child5
      static bool?   accountExists
      static bool?   isAdmin
  → setUserData(DocumentSnapshot) populates all fields from Firestore
  → resetUserData() nulls all fields (called on signOut)
  → setEmail(email) updates just the email field
  → isEmpty() returns true if uid == null

FIRESTORE COLLECTIONS:

      state:         string
      zip:           string
      spouse:        string
      spouseEmail:   string

      mother:        string

      accountExists: boolean
      isAdmin:       boolean

  announcements/
    {auto-id}/
      name:      string   (announcement title)

11. STATE MANAGEMENT
==============================================================

APPROACH: Provider (global) + setState (local)

Global:
  AuthService extends ChangeNotifier
  → Registered at root via ChangeNotifierProvider<AuthService>
  → Provides auth state stream to Wrapper and any screen that needs it
  → No other ChangeNotifiers; no Riverpod, Bloc, GetX, etc.

Local:
  All screen widgets are StatefulWidgets using setState()
  SearchHelper and EditInfo hold UI state and call a setState callback
  provided by the parent screen — tight coupling between helper and UI

User Data Cache:
  UserData is a static class (essentially a global singleton)
  Populated after login, cleared on logout
  No reactive listeners — screens read UserData directly on build
  This means a UserData change does NOT auto-rebuild dependent widgets

12. NAVIGATION PATTERNS
==============================================================

NO named routes used anywhere.

Auth navigation:
  Wrapper rebuilds based on stream → pushes entirely new widget tree
  Not using Navigator at auth level — widget tree replacement

Screen-to-screen:
  Navigator.push / Navigator.pushReplacement used in auth screens
  Example: verify_screen → send_Email → verify_screen (pushReplacement)

Home tabs:
  IndexedStack with bottom BottomNavigationBar
  setState(currentIndex) switches tab, no Navigator involved
  All 3 tabs are built once and preserved in memory

Dialogs / Popups:
  showDialog() → AlertDialog or custom dialog widget
  Navigator.pop() to close

Key navigation gap:
  No deep linking support
  No route guards other than the Wrapper stream check
  Back button behavior not explicitly handled

15. CODE QUALITY ISSUES (WHAT NEEDS TO CHANGE IN REFACTOR)
==============================================================

ARCHITECTURE:
  [ ] UserData static class is an anti-pattern — use Provider or Riverpod
  [ ] Business logic mixed into UI helper classes (SearchHelper, EditInfo)
      These classes both manage Firestore calls AND build dialog widgets
  [ ] No repository pattern — Firestore called directly from services and helpers
  [ ] future_builder_class.dart is dead code — delete it
  [ ] Duplicate screens: admin/normal screens share identical logic with
      minor differences — could be unified with role-based rendering

STATE MANAGEMENT:
  [ ] setState callbacks passed into helper classes (SearchHelper.resetUI) is fragile
  [ ] Static UserData doesn't trigger rebuilds — screens read stale data silently
  [ ] Consider Riverpod or Provider with a UserDataNotifier

SEARCH:
  [ ] Prefix search is case-sensitive and fragile
  [ ] Relies on TextFormatting.formatEnteredText() to title-case all queries
  [ ] No full-text search — Firestore doesn't support it natively
      Consider Algolia integration or storing lowercase copy fields for search
  [ ] Search only works for name, gaam, city — can't search by phone or partial email

UI / UX:
  [ ] UI sizing uses SizeConfig everywhere but calculations are complex and manual
      Consider using MediaQuery.sizeOf(context) or flutter_screenutil
  [ ] gradient background (white → blue) is dated — modernize design
  [ ] TableRowColumns widgets in dialogs are functional but visually plain
  [ ] No loading states shown within screens (only full-screen LoadingWheel)
  [ ] No empty state illustrations
  [ ] Events tab is a non-functional placeholder — implement or remove

VERSIONS:
  [ ] Dart SDK constraint must change from <3.0.0 to >=3.0.0
  [ ] All Firebase packages need major version bumps (4.x → 5.x)
  [ ] google_fonts 4.x → 6.x
  [ ] compileSdkVersion 33 → 34 or 35
  [ ] flutter_lints 1.x → 4.x (many new lint rules to address)
  [ ] minSdkVersion 19 may need to increase to 21 for newer Firebase SDKs

SECURITY:
  [ ] Firestore security rules not visible in this repo — must audit
  [ ] isAdmin determined by a Firestore field — ensure rules prevent self-elevation
  [ ] Firebase API keys in firebase_options.dart (acceptable for mobile but note it)

CODE HYGIENE:
  [ ] Commented-out code in events tab toggle should be removed or implemented
  [ ] No unit or widget tests
  [ ] No CI/CD pipeline
  [ ] google_fonts will download fonts at runtime — consider bundling assets
